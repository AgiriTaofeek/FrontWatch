# Security Incident Response

## Lifecycle

```text
Detect
 ↓
Triage
 ↓
Contain
 ↓
Eradicate
 ↓
Recover
 ↓
Validate
 ↓
Post-incident review
```

## Potential Incidents

```text
credential compromise
tenant isolation failure
data exfiltration
malicious SDK release
vulnerable dependency
infrastructure compromise
```

## Immediate Priorities

1. Protect customers.
2. Stop further exposure.
3. Preserve evidence.
4. Determine scope.
5. Rotate/revoke affected credentials.
6. Patch the vulnerability.
7. Validate recovery.

## Evidence

Preserve relevant:

```text
audit logs
application logs
deployment records
access records
security alerts
```

## Customer Communication

Define procedures for notifying affected self-hosted customers according to contractual and regulatory requirements.
