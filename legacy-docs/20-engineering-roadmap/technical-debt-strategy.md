# Technical Debt Strategy

## Categories

```text
correctness debt
architecture debt
performance debt
security debt
test debt
documentation debt
```

## Prioritization

Prioritize debt that:

```text
blocks delivery
creates security risk
causes incidents
limits scale
creates repeated engineering cost
```

## Avoid

Do not create a large "technical debt later" bucket.

Create explicit backlog items with context and impact.

## Rule

Fast MVP implementation is acceptable when the boundary is intentional and the follow-up work is visible.
