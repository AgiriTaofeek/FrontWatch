# Sprint Planning

## Sprint Inputs

Pull from:

```text
MVP backlog
dependencies
risk register
bugs
technical debt
operational needs
```

## Capacity

Do not plan 100% of team capacity.

Reserve capacity for:

```text
bugs
support
incidents
reviews
technical discovery
```

## Story Selection

Prioritize stories that move the critical path forward.

## Sprint Goal

Every sprint should have a clear outcome, for example:

```text
"An engineer can capture and investigate production frontend errors."
```

## Review

At the end of the sprint, demonstrate working software rather than completed tickets.
