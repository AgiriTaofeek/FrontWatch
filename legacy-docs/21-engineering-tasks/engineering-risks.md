# Engineering Task Risks

## R01 — Too many tasks before first demo
Use the first vertical slice.

## R02 — API contract drift
Use shared contracts and contract tests.

## R03 — SDK compatibility explosion
Maintain an explicit support matrix.

## R04 — Data plane over-engineering
Start with a small number of Go components and benchmark.

## R05 — Control/data boundary blurs
Maintain the Bun/Go ADR and ownership boundaries.

## R06 — Security added late
Embed security work into every epic.

## R07 — Testing delayed
Testing is part of feature completion, not a final phase.
